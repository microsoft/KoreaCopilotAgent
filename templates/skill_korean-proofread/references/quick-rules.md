# 빠른 점검 규칙 (경량 모드 전용)

짧은 텍스트나 빠른 점검을 요청할 때 SKILL.md가 이 파일만 불러 쓴다. 회사 문서에서 자주 나오는 오류만 추렸다. 전체 분류는 references/ai-tell-and-translationese.md와 references/public-language.md에 있다.

## 자주 나오는 오류 (심각도 · 처방)

| ID | 패턴 | 심각도 | 처방 |
|---|---|---|---|
| P1 | 줄표(—) 문장 중간 삽입 | 🔴 | 쉼표·괄호로 바꾸거나 문장 분리 |
| P2 | 가운뎃점(·)으로 긴 구 나열 | 🟡 | 쉼표나 '와/과'로. 애매하면 쉼표 |
| P3 | "~에 의해" 피동 | 🔴 | 주체를 주어로 능동 전환 |
| P4 | "~에 대한/대하여" 남발 | 🟡 | 목적격 조사로 축약 |
| P5 | "~에 있어서" | 🟡 | 삭제하거나 "에서/에" |
| P6 | "~할 필요가 있다" | 🟡 | "~해야 한다" |
| P7 | "~하는 것이 가능하다" | 🟡 | "~할 수 있다" |
| P8 | "~을 가지다"(have 직역) | 🟡 | "있다" 또는 구체 동사 |
| P9 | 이중피동 "되어졌다/요구되어진다" | 🔴 | "되었다/필요하다" |
| P10 | 명사문 "확보가 필요함" | 🟡 | 동사문 "확보해야 함" |
| P11 | 어려운 한자어 "제고/시행" | 🟡 | 쉬운 말 "높임/실시" |
| P12 | 빈 강조어 "핵심적인/다양한/그 어느 때보다" | 🟡 | 구체 정보로 대체 |
| P13 | 과장어 "혁신적인/게임 체인저" | 🟡 | 사실 서술로 |
| P14 | 종결어미 "~습니다" 단조 반복 | 🟡 | 종결 다양화 |
| P15 | 주어와 서술어 비호응 | 🔴 | 호응 맞추기 |
| P16 | 높임법 불일치 | 🔴 | 글 전체 높임 통일 |
| P17 | 만연체(절 3개 이상) | 🟡 | 문장 나누기 |

## 자체 점검 (교정 후)
1. 고유명사·수치·날짜·인용을 원문 그대로 보존했는가
2. 문서 유형에 맞는 문체와 격식을 유지했는가
3. 높임법이 글 전체에서 일관되는가
4. 줄표 남용과 가운뎃점 남용이 남아 있지 않은가
5. 원문에 없던 내용을 임의로 지어내지 않았는가
